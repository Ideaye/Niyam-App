1. What iOS Niyam is — and honestly isn't

The vow survives; the choreography changes. iOS structurally forbids one app from watching another launch and painting a live overlay over it. What Apple sanctions instead is the Screen Time API: Niyam "shields" the user's chosen apps, and opening one presents a system shield screen that we style. The pause-before-the-scroll happens there — mantra line, sacred moment, Continue — then a grace window opens, exactly mirroring Android's UnlockGrace. The full reading experience (in-script text, ring, meaning, streak recording) lives inside the Niyam app.

What the shield can and cannot do (verified): customizable = background color + blur, an icon image, title, subtitle, one or two buttons with label/color. NOT possible = gradients, animation, a live countdown, custom views (Apple feedback FB14237883 confirms static-snapshot design), or opening our app directly from the shield button (ShieldActionResponse is only .none/.defer/.close). One quirk: minutes spent staring at the shield count as "usage" of the blocked app in Screen Time stats.

2. Blocking mechanism (the core loop)

  1. Selection: user picks apps via Apple's FamilyActivityPicker. Apple returns opaque tokens — we never learn which apps they chose, and we cannot pre-list "Instagram/YouTube" the way Android's AppCatalog does. (Privacy-positive; onboarding copy adapts.)
  2. Shield: ManagedSettingsStore.shield.applications = tokens. Opening a shielded app shows our configured shield: bottle-green background, Niyam icon, the current mantra's first line as title, its roman/translation line as subtitle, primary button "I've read it — Continue".
  3. Pause enforcement: button tap → ShieldActionDelegate responds .defer, waits the configured pause length (15–60s; the shield stays up, static — no visible countdown, an honest iOS compromise), then removes that app's token from the shield set.
  4. Grace: a DeviceActivitySchedule re-shields the app after the 5-minute grace window (same semantics as Android's UnlockGrace: granted only by Continue).
  5. Interval check-in (v1.1, not v1): DeviceActivityMonitor usage-threshold events map cleanly to the 30/60/120-min check-in — deferred to keep v1 tight.

Extensions required: ShieldConfiguration extension + ShieldAction extension + DeviceActivityMonitor extension, sharing state with the app via an App Group. Each needs the Family Controls entitlement (distribution approval covers app + extensions; Apple reviews the request in days-to-weeks — filed early, see §10).

4. Architecture

  • Repo: monorepo — new ios/ directory beside app/. One mantras.json source of truth (build step copies it into the iOS bundle). Website/Vercel unaffected.
  • Stack: Swift 5.10+, SwiftUI, min deployment iOS 16 (Screen Time APIs matured there; covers the overwhelming share of active iPhones). SwiftData for read-events (Room's mirror). No third-party deps except supabase-swift.
  • Targets: app + 3 extensions (§2) + App Group group.com.myniyam.app for shared prefs (current mantra, pause config, grace state).
  • Bundle id: com.myniyam.app (matches Android's application id; independent namespace on Apple).

5. Auth & sync

  • Sign in with Apple is mandatory (App Store rule when third-party login is offered) + Google sign-in for parity. Both native via supabase-swift.
  • Account identity: Supabase links providers by verified email. Caveat: Apple users who choose "Hide My Email" get a private-relay address → a returning Android user signing into iOS with Apple would create a separate account. Mitigation: onboarding copy nudges "use the same Google account as on Android" for cross-device users; Apple sign-in primarily serves iOS-first users.
  • Sync: reuse practice_state + favourites tables and Android's push-local-then-sync semantics (push on background, seed on sign-in). Streaks stay device-local (same as Android). Entitlements/billing tables: untouched, dormant.
  • Delete account: same delete-account Edge Function.

6. Content & localization

  • Bundled mantras.json (identical file) + OTA via the same content bucket and app_config.content_version. RemoteConfig keys reused; iOS ignores Android-only keys (blockable_apps — meaningless under opaque tokens; min version gets an iOS sibling key min_supported_build_ios).
  • Chrome: port the 8 languages from values-*/strings.xml → Localizable.xcstrings via a conversion script (one-time + re-runnable; keeps Android as the translation source of truth). All the native-review quality lands on iOS for free.

7. UI

Ports the founder-approved Android v2 design system — Sunrise/dark gradients, bottle-green/eggshell/orange tokens, Outfit (licensed, bundled), floating 24dp cards, content-below-top-bar composition, 4-tab bottom bar. No new visual design is being proposed; screens map 1:1 to their Android siblings except where iOS idiom demands (system back-swipe, sheet-style pickers, FamilyActivityPicker replacing the app grid). Founder gallery veto happens on TestFlight screenshots at P7, same as Android's emulator galleries.

11. Risks & open questions

  • Q1 — streak semantics (needs founder call at P5): on Android, the overlay Continue records the read. The iOS shield cannot. Options: (a) reads count only when done inside the app (purer, but shield-Continue users build no streak), or (b) the app infers a read when it next opens after a grace grant (approximate). I lean (a) + a Home nudge; decide at P5 with real feel.
  • Entitlement risk: Apple occasionally rejects Family Controls requests for non-parental-control uses; digital-wellbeing blockers are routinely approved (One Sec, Opal precedents), but it's Apple's discretion. Mitigation: request text positions Niyam squarely as digital wellbeing.
  • Shield-usage accounting quirk (time on shield counts as app usage in Screen Time stats) — cosmetic, but worth a FAQ line.
  • Free-tier Supabase auto-pause (forlater #18) bites iOS testing the same as Android — the Pro decision matters more with two clients.
  • Parallel-track discipline: iOS work must never touch app/ (Android) files. The shared surfaces are exactly: mantras.json, Supabase schema/functions, website. Any change to a shared surface gets flagged before making it.
